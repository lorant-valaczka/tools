# Applications

Applications do two jobs: they prove the system works, and they produce new rules. Both matter, so every surface ends with a write-back step.

## The fixed test set for directions

Pick 4–6 surfaces from the brand's own top-priority surfaces, covering:
- **a large statement:** a cover, hero section or poster;
- **a dense content page:** an article, report page, product page or menu;
- **a small-size use:** favicon, app icon or avatar;
- **a social format:** a post or a banner;
- **one brand-specific surface:** packaging, signage, a product screen, a CV header, a shop window…

Every direction is shown on the same set, with the same content. Reuse the set later: the finished system should pass the same test the directions did.

## Order of application

The principle: small and fast first, dense typography early, templates before content, publishing gated by licences rather than design gated by them.

The order is a default, not a law. A hard production deadline (a sign, a packaging run, a print order) can move that surface forward. When it does, say so in the plan, log it, and still run the small-size check on the mark before the files go to production.

1. **Small identity surfaces**, as soon as the mark and colour are closed: avatar, favicon, app icon, link-preview (OG) image. They are quick and expose small-size problems early.
2. **Dense typography:** a document, report page, CV or menu. This tests the typeface, the diacritics and the small sizes.
3. **Templates before content:** deck masters (cover, divider, closing, the content layouts), social templates, document templates. When templates are built in the middle of real content work, the result is one-off components that don't fit together.
4. **Real content, then the second language.** When translating, check that the formatting survived: bold, links and colour runs are often lost when text is replaced.
5. **Email signature:** fallback fonts, hosted images, how it looks in dark-mode email clients.
6. **Website or product UI:** design can start as soon as the tokens exist. The web font licence gates publishing, not design. Imagery and icon decisions made here write back into the book.
7. **Physical surfaces:** print, packaging, signage, merchandise. Ask for proofs; verify colour conversions (CMYK, Pantone) and materials. At levels 1 and 2, draft the message the person sends to the supplier (see `communication-levels.md`), including the request for the supplier's file requirements.
8. **Personal brands:** ask early for the person's own sketches for social surfaces (banner, avatar). They often already know the composition they want, and it changes the concept.

## Surface menus by brand type

Use these to prompt the surface list at intake; the user picks and orders.

| Brand type | Typical surfaces |
|---|---|
| Personal | avatar, social banners, CV, portfolio website, deck, email signature, business card |
| Product or SaaS | app icon, product UI theme, website, social, documentation or help centre, deck, email templates |
| Local business or retail | signage, shop front, menu or price list, packaging and bags, social, map and review-site profiles, loyalty card |
| Organisation or NGO | reports, event materials, social, website, co-branding lockups with partners |
| Packaged product | pack family, shelf impact, e-commerce images, point-of-sale materials |

## Write-back, at the end of every surface

Ask three questions:
1. Did this surface need a rule that isn't in the book?
2. Did it need an exception? If yes, name it and put it in one place.
3. Did any value change?

If any answer is yes: update the chapter, the log and the tokens, and bump the brandbook version.
